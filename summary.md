# Synthea to PyTorch database transformer

## 1. Project purpose

This project converts synthetic healthcare records generated by Synthea into patient/event sequences for representation learning. The current model has three intended objectives:

1. Encode a patient's structured context with a causal Transformer.
2. Reconstruct or answer questions about masked event attributes using only positive patient sequences.
3. Optionally distinguish real patient event combinations from corrupted or cross-patient combinations.

The reconstruction objective is conditional modeling: given the encoded context and a question, predict an event concept, a column, a value, or a time-related quantity. The discrimination objective is separate and should not be confused with estimating a conditional probability.

## 2. Data pipeline

### Source and normalized storage

Synthea CSV files in `dataset/csv/` contain patients and clinical tables such as encounters, conditions, medications, observations, procedures, allergies, careplans, imaging studies, immunizations, devices, and supplies.

The pipeline uses DuckDB to read and normalize these files. The normalized Parquet files in `dataset/parquet/` use shared names such as `patient_id`, `start_time`, and `stop_time`, safe casts for timestamps and numeric values, and filters for rows without a valid patient (and, where required, encounter). DuckDB views in `dataset/healthcare.duckdb` expose the Parquet data without requiring a second full copy.

### Vocabulary

`build_dictionary.py` creates `dataset/ml/vocab.pt`. The vocabulary contains special values such as `None`, positive infinity, and `NaN`, table names, column names, and namespaced categorical values such as `observations.code.8302-2` or `patients.gender.M`. Continuous values are not placed in the vocabulary.

### Unified event export

`041-totorch.py` builds a unified event relation from the clinical tables. Each event contains a patient, encounter, event type, code, optional numeric value, start time, stop time, and ordering metadata. Numeric observations are used as continuous values; imaging uses the body-site code as its event code.

Events are normalized relative to the patient's birth time where available, ordered chronologically per patient, assigned a zero-based event index, and written as compressed Parquet part files. Patients are deterministically assigned to 20 hash buckets:

- buckets 0--15: train
- buckets 16--17: validation
- buckets 18--19: test

The export also writes a `patient_index.parquet` containing patient metadata, event-file locations, event counts, time ranges, and precomputed patient feature tokens.

## 3. Token schema

Event and patient rows use nine numeric channels. Values are stored as `DOUBLE` in Parquet so categorical IDs and continuous values can share one tensor, then categorical channels are converted to integer IDs by the model.

| Channel | Meaning | Representation |
|---|---|---|
| `token_0` | Concept/code | Vocabulary ID |
| `token_1` | Continuous value | Numeric value or `NaN` |
| `token_2` | Value-presence mask | `1.0` when `token_1` is present, otherwise `0.0` |
| `token_3` | Start time / age | Seconds from birth or start, or `inf` |
| `token_4` | Duration | Non-negative seconds, or `inf` |
| `token_5` | Time delta | Seconds since the previous event; `0.0` for patient features |
| `token_6` | Source table | Vocabulary ID |
| `token_7` | Source column | Vocabulary ID |
| `token_8` | Event type | Numeric event-type index |

Patient rows contain seven feature positions:

| Position | Feature | `token_0` | `token_1` / `token_2` |
|---:|---|---|---|
| 0 | gender | categorical ID | `NaN`, `0.0` |
| 1 | race | categorical ID | `NaN`, `0.0` |
| 2 | ethnicity | categorical ID | `NaN`, `0.0` |
| 3 | birthplace | categorical ID | `NaN`, `0.0` |
| 4 | city | categorical ID | `NaN`, `0.0` |
| 5 | income | null ID | income, presence mask |
| 6 | padding/reserved feature | null ID | `NaN`, `0.0` |

Patient positions also carry patient start time, patient duration, zero time delta, the `patients` table ID, a feature column ID, and event type index 0.

## 4. PyTorch loader

`051-load.py` provides `PatientEventsDataset`. It loads either the patient index eagerly or queries it lazily with DuckDB, fetches the required Parquet event files, groups events by patient, converts them to tensors, and combines the seven patient positions with event positions. Time channels 3--5 are scaled by `TIME_SCALE` before entering the model. Sequences are truncated or sampled to `context_length`, padded with a boolean padding mask, and may be shuffled for experiments.

The negative sampler keeps the patient prefix and can replace a subset of event positions with events from another patient. Complete event records should be swapped together; independently swapping channels creates invalid records and an artificial shortcut.

## 5. Current embedding implementation

`model/embedding.py` currently creates these feature embeddings per sequence position:

1. `token_0`: categorical concept embedding.
2. `token_1` plus `token_2`: frequency-featured numeric projection, or a categorical missing-value embedding.
3. `token_3`, `token_4`, `token_5`: three calls through a shared time frequency projection, with an infinity/missing categorical embedding.
4. `token_6` and `token_8`: categorical table and event-type embeddings.

The current `forward()` concatenates these into seven feature slots and sums the slots in `DBTransformer.forward()`. `token_7` (source column ID) is present in the data schema but is currently not embedded by this code. The CLS parameter is placed in the first feature slot of a prepended sequence position; the remaining feature slots of that position are zero.

The frequency projection concatenates the raw value, sine features, and cosine features before an MLP. Time frequencies are fixed from century through second-scale periods. Missing time values are replaced for projection and then replaced with a learned categorical infinity embedding.

## 6. Current Transformer and decoder status

`model/transformer.py` defines the intended causal Transformer encoder using `nn.TransformerEncoder` with `batch_first=True`, a causal mask, and the dataset padding mask. `model/model.py` sums per-feature embeddings before passing the sequence to the encoder.

The decoder is currently a scaffold. It defines separate candidate layers for categorical/column outputs, numeric values, and time values, but its `forward()` and loss wiring are not complete. The existing `DecoderLayer` should not make hard missing-value decisions during training; missingness should be represented by logits and trained with a differentiable loss.

## 7. Recommended reconstruction design

The causal encoder output at position $i$ represents information available before or at that position, depending on the exact causal-mask convention. For reconstruction, define an explicit query for each target rather than reusing an accidental feature embedding. Useful query types include:

- concept/column given context and time;
- value given context, concept, and column;
- time given context and concept/event;
- a fully unknown event query that predicts a structured event.

Use a learned query embedding for the question type, plus embeddings for the known conditioning fields. Encode missing fields with explicit learned `[MASK]` or unknown embeddings, not all-zero vectors. A practical first version is:

```text
context tokens -> causal encoder -> context representation h
question fields -> query representation q
fusion(h, q) -> task-specific prediction heads
```

The simplest fusion is concatenation followed by an MLP. A small query cross-attention decoder becomes useful when the answer must attend to many different encoder positions or when the query itself has multiple tokens.

Use separate heads for different output domains: categorical logits with cross-entropy, numeric regression with a masked Huber/Gaussian loss, time regression with a scaled/log-transformed target, and a missingness logit with binary cross-entropy. Compute reconstruction loss only on valid positive targets, while retaining the missingness loss where missingness is observed.

## 8. Discrimination objective

Positive examples contain compatible patient context and events. Negative examples replace complete event records with records from another patient. With independently sampled negatives and equal class priors, the optimal discriminator logit estimates

$$
\log \frac{p(x,y)}{p(x)p(y)} = \operatorname{PMI}(x,y).
$$

If negatives are matched or restricted, it estimates a density ratio relative to that negative-sampling distribution instead. The discriminator should see neither a corruption marker nor the swap mask. Reconstruction is trained on clean positive sequences; discrimination may use corrupted sequences.

## 9. Initial experiments

Start with the following controlled baselines:

1. Add `token_7` and use learned per-channel gates before summing features.
2. Compare sum pooling against concatenation plus a projection layer.
3. Keep the three time channels separate through learned type embeddings and either gated sum or concatenation.
4. Train a shared query MLP with task-specific output heads, then compare it against separate MLPs.
5. Evaluate chronological and permuted contexts with the same losses and corruption policy.

Track per-task accuracy/calibration for categorical outputs and MAE or negative log likelihood for numeric/time outputs. Also inspect whether the model predicts missingness and common categories without using context.
